# 新课讲授与带做实验

## 什么时候用

开始学习一节新的 Linux / RHCSA / 运维课程并在虚拟机（node1 / node2）上动手做实验时。

## 我会给你

- 本课编号、主题和目标（如 B2-2 MySQL 备份与恢复）
- 当前实验环境状态（node1 / node2 上的服务、库表、端口等）
- 每一步在终端执行后的真实输出

## 你要做的

1. **先讲原理，再动手做实验。** 在给出第一条实操命令前，用精炼的结构讲清：
   - 为什么要学这个机制、解决什么问题
   - 核心概念对比与取舍（用小表格）
   - 本次实验的步骤路线图
2. **新术语先解释再用。** 第一次出现的概念、缩写或机制（如 InnoDB、事务快照、DDL/DML、SIGHUP、AVC）要先用大白话讲明白，不要直接甩术语。
3. **分步推进，每步只给当前这一小段命令。**
   - 说明在 node1 还是 node2 执行，以及关键参数的作用。
   - 等我贴出真实终端输出后，先解读输出、回答疑问，再给下一步。
4. **实时抓住报错和踩坑。**
   - 我在终端遇到报错、拼写错误或意外现象时，讲清底层原因（如 bash 重定向先于命令启动、SQL `near '...'` 定位、库名与表名混淆），留作笔记的「踩坑」素材。
5. **实验结束后按 `skills/lab-wrapup.md` 收尾。**
   - 生成 `labs/YYYY-MM-DD-主题.md`，补进当周 `cheatsheets/weekN-*.md`。
   - 在对话中出 5 道课后面试题（遵守 `skills/review-quiz.md`：一题一问、不超纲），我作答后批改并写入笔记，最后 `git add` / `commit` / `push`。

## 不要做

- 不要还没讲原理就直接甩命令让我执行。
- 不要使用未解释的新术语。
- 不要一次把整节课的所有命令全贴出来。
- 不要把实验密码或任何单位真实数据写进仓库（密码一律写 `'...'`）。
- 不要在课后题里叠问、连问或超纲。
