# SSH：主机密钥、密钥登录、sshd 加固、scp/rsync

- 日期：2026-10-22（W4-D2）
- 考点：RHCSA EX200 —— 配置基于密钥的 SSH 认证；在系统间安全传输文件；限制 root 远程登录
- 环境：Rocky Linux 10.2（VirtualBox），node1（客户端）、node2（服务端，只在 node2 上改 sshd）
- 状态：完成
- 来源：根据课程对话和终端记录整理

## 目标

分清主机密钥和用户密钥，配好 node1 → node2 的密钥登录，在 node2 上禁止密码和 root 登录，验证 sshd 的"第一个值生效"规则，用 scp/rsync 传文件。

## 关键概念

- 三个阶段：传输层（协商加密、**服务器出示主机密钥** → known_hosts）→ 用户认证（公钥/密码）→ 会话。
- 主机密钥证明服务器是真的：私钥 `/etc/ssh/ssh_host_*_key`（600 root），公钥进客户端 `~/.ssh/known_hosts`。用户密钥证明用户是本人：私钥 `~/.ssh/id_ed25519`，公钥进服务端 `~/.ssh/authorized_keys`。
- 公钥认证：客户端用私钥对本次会话数据签名，服务端用公钥验证，私钥不离开本机；密码认证会把密码发给服务器 → 首次连接核对指纹防中间人。
- StrictModes：`~`、`~/.ssh`、`authorized_keys` 别人可写 → 拒绝用公钥、回退密码，原因只写在**服务端日志**。
- sshd_config：同一关键字**第一个值生效**（与 systemd drop-in 相反）；主配置开头 `Include /etc/ssh/sshd_config.d/*.conf`，按文件名顺序读 → drop-in 优先于主配置，`05-` 优先于 `10-`。
- `sshd -T` 每次**重新读磁盘文件**计算结果，不代表正在运行的 sshd；改完/删完配置都要 `systemctl reload sshd`。reload 不断开已有会话。
- RHEL 10 默认 `PermitRootLogin prohibit-password`（`sshd -T` 显示旧名 `without-password`）；node2 上没有任何文件设置它，是编译默认值。
- OpenSSH 9.8+：`LoginGraceTime` 默认 120 秒内没完成认证就断开；**PerSourcePenalties** 会对"有不良行为"的源 IP 暂时拒绝新连接。
- `ssh-keygen` 不带 `-t` 默认 ed25519。
- `sudo ssh/scp/rsync` 以 root 身份连接，用 `/root/.ssh` 的 known_hosts 和密钥。

## 关键步骤

```bash
# 主机密钥指纹（node2）与首次连接核对（node1）
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
sudo sshd -T | grep -Ei 'permitrootlogin|passwordauth|pubkeyauth'
sudo grep -ri permitrootlogin /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
ssh-keygen -R node2; ssh fqh@node2

# 密钥登录
ssh-keygen
ssh-copy-id fqh@node2
ssh fqh@node2 'hostname; id'

# 权限故障
chmod 664 ~/.ssh/authorized_keys          # node2
sudo journalctl -u sshd -n 20 --no-pager
chmod 600 ~/.ssh/authorized_keys

# 加固（node2）
sudo tee /etc/ssh/sshd_config.d/10-lab.conf << 'EOF'
PermitRootLogin no
PasswordAuthentication no
EOF
sudo sshd -t && sudo systemctl reload sshd
sudo sshd -T | grep -Ei 'permitrootlogin|passwordauth'

# 第一个值生效：99-test.conf 写 yes → 仍是 no；改名 05-test.conf → yes；删除后 reload
sudo mv /etc/ssh/sshd_config.d/99-test.conf /etc/ssh/sshd_config.d/05-test.conf
sudo rm /etc/ssh/sshd_config.d/05-test.conf && sudo systemctl reload sshd

# 传文件
scp /etc/hosts fqh@node2:/tmp/hosts.node1
scp fqh@node2:/etc/os-release /tmp/
rsync -av ~/rs/a  fqh@node2:/tmp/rs1/     # → /tmp/rs1/a/f1
rsync -av ~/rs/a/ fqh@node2:/tmp/rs2/     # → /tmp/rs2/f1
```

## 验证

| 检查项 | 命令 | 预期结果 | 结果 |
|---|---|---|---|
| 主机私钥权限 | `sudo ls -l /etc/ssh/ssh_host_*` | 私钥 600 root，公钥 644 | ✅ |
| 指纹一致 | node2 `ssh-keygen -lf`、node1 首次连接提示 | 相同 | ✅ `SHA256:sP2Am8...E7Wk` |
| 默认 root 登录策略 | `sshd -T`、`grep -ri` | prohibit-password，无文件设置 | ✅ 只有注释行 |
| 默认密钥类型 | `ssh-keygen` | ed25519 | ✅ |
| 密钥登录 | `ssh fqh@node2`、服务端日志 | 不问密码，`Accepted publickey` | ✅ 指纹 `QJRh...nuHk` |
| 权限错误被拒 | `chmod 664` 后登录、日志 | 回退密码；`bad ownership or modes` | ✅ |
| 加固生效 | `sshd -T` | permitrootlogin no、passwordauthentication no | ✅ |
| 只用密码被拒 | `ssh -o PubkeyAuthentication=no fqh@node2` | Permission denied | ✅（reload 后再测一次也 ✅） |

## 踩坑

- **首次连接确认指纹太慢 → 被断开，之后又被拒**：`Connection closed by ... port 22`，再连 `kex_exchange_identification: read: Connection reset by peer`。服务端日志：`Timeout before authentication`（LoginGraceTime 120 秒）→ `drop connection ... penalty: exceeded LoginGraceTime`（PerSourcePenalties）。等惩罚期过后自动恢复。
- `ssh -v ... | tail -20` 看起来卡住 → 在等密码；密码提示直接写终端，`tail` 要等 ssh 结束才输出。
- `ls /etc/ssh/sshd_config.d/` Permission denied → 目录只有 root 能进，要 sudo。
- **删掉 05-test.conf 后没 reload** → 运行中的 sshd 仍允许密码登录（`sudo rsync` 时用密码登录成功），而 `sshd -T` 显示 no → `sshd -T` 读的是磁盘文件。补 reload 后验证被拒。
- `rsync /etc/ssh/ ...` 不带参数 → `skipping directory .`（没有 `-r`，`-a` 包含它）。
- 普通用户 rsync `/etc/ssh` → 私钥和 sshd_config `Permission denied (13)`，退出码 23。
- **`sudo rsync -av /etc/ssh/ ...` 把 node1 的主机私钥拷到了 node2 的 /tmp** → 主机身份泄露（实验素材选得不好）→ 已 `rm -rf /tmp/ssh-copy`。不要拿 `/etc/ssh` 练传输。
- `sudo rsync` 又问指纹、要密码 → 以 root 身份连接，root 没有 known_hosts 记录和密钥。

## 卡点 / 没想明白的

- 达标题 4：以为 `HOST IDENTIFICATION HAS CHANGED` 时输入 yes 就行 → 主机密钥变了 ssh 直接拒绝，不给 yes 选项；要先用控制台等其他途径核对新指纹，再 `ssh-keygen -R 主机名`（IP 也有记录的话一起删）后重连。

## 回忆题

1. （概念）主机密钥和用户密钥各证明什么？私钥、公钥分别放在哪台机器的哪里？
<details><summary>答案</summary>

主机密钥证明服务器是真的：私钥在服务端 `/etc/ssh/ssh_host_*_key`，公钥记在客户端 `~/.ssh/known_hosts`。用户密钥证明用户是本人：私钥在客户端 `~/.ssh/id_ed25519`，公钥在服务端 `~/.ssh/authorized_keys`。
</details>

2. （操作）配置 node1 的 fqh 免密登录 node2，并在 node2 上禁止密码和 root 登录、确认生效。
<details><summary>答案</summary>

`ssh-keygen; ssh-copy-id fqh@node2` → node2：`/etc/ssh/sshd_config.d/10-lab.conf` 写 `PermitRootLogin no`、`PasswordAuthentication no` → `sshd -t && systemctl reload sshd` → `sshd -T | grep -Ei 'permitroot|passwordauth'` → node1 `ssh -o PubkeyAuthentication=no fqh@node2` 被拒。
</details>

3. （排障）配好公钥登录还要密码；`sshd_config` 末尾加了 `PasswordAuthentication no` 密码还能登录。各怎么查？
<details><summary>答案</summary>

前者：客户端 `ssh -v` 看是否 Offering public key、私钥权限；服务端 `journalctl -u sshd`（bad ownership or modes）、`authorized_keys` 内容和 `~`/`.ssh`/`authorized_keys` 权限、`sshd -T | grep pubkeyauth`。后者：第一个值生效，`Include` 在主配置开头，drop-in 或更前面的行已设成 yes → `sshd -T` 看最终值，`grep -ri passwordauth /etc/ssh/sshd_config /etc/ssh/sshd_config.d/` 找来源，把设置写进靠前的 drop-in；以及确认改完 reload 了。
</details>
