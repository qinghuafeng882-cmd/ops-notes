## 正确做法

```bash
for u in alex lisa tom; do echo "$u:RedHat2026" | sudo chpasswd; done
sudo grep -E '^(alex|lisa|tom):' /etc/shadow | cut -d: -f1,2   # 哈希应以 $6$ 或 $y$ 开头
id alex                                                        # 验证附加组用 id，不用 cat passwd

sudo visudo -f /etc/sudoers.d/webadmins   # %webadmins ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart httpd
sudo chmod 0440 /etc/sudoers.d/webadmins; sudo visudo -c; sudo -l -U alex

sudo chmod 3770 /srv/webdata               # 3 = SGID(2) + Sticky(1)
sudo -u alex touch /srv/webdata/alex.txt; sudo -u lisa rm -f /srv/webdata/alex.txt

sudo find /usr -type f -perm -4000 | sudo tee /root/suid.txt; sudo wc -l /root/suid.txt
```

## 踩坑

- `useradd -p 明文` → `-p` 要的是加密后的哈希，明文写进 shadow 后永远登录不了，且不报错 → 用 `chpasswd`。
- tom 的密码写成 `RadHat2026`（拼写错误）。
- 特殊权限数值：**SUID 4、SGID 2、Sticky 1**。
- 写出"应该会怎样"不等于验证过 → 实际执行并贴输出。
- `for ...; do ... | sudo chpasswd done` 漏了 `;`，出现 `>` 续行提示符 → Shell 认为命令没写完在等后续输入 → Ctrl-C 后补上 `; done`。
- `sudo sed 's/^PASS_MAX_DAYS .*/.../' /etc/login.defs` 没改成功 → 没加 `-i`，只打印到屏幕；而且 login.defs 里关键字和值之间很可能是 Tab 不是空格（推测，用 `grep '^PASS_MAX_DAYS' /etc/login.defs | cat -A` 确认，Tab 显示为 `^I`）。
- 第 2 题第一次误写成 60，又用 `sed -i.bak` 改成 90 → 第二次的 `.bak` 覆盖了第一次的备份，原始的 99999 版本丢了（D6 的教训再现）→ 备份名加时间戳。
- `userdel testdefs` 不加 `-r` 后重建同名用户 → 提示家目录和邮箱已存在 → 删除用户用 `userdel -r`。
- 第 7 题：`dnf install -y --disablerepo=...` 没写包名；没有写 `/etc/yum.repos.d/w2repo.repo`，所以 dnf 不认识 w2repo。
- 第 7 题：`.repo` 文件写成 `/etc/yum.repos.d/w2repo`（没有 `.repo` 后缀）→ 仍然 `Unknown repo` → dnf 只读 `.repo` 结尾的文件，改名后正常。（和 drop-in 必须 `.conf` 结尾同一类：后缀不对，系统直接忽略）
- 第 7 题：`sudo dnf remove -y zip` → 事务里 `perl` 依赖 zip 被一起删，perl 带进来的 perl-* 模块、gcc-c++ 等成了"不再需要的依赖"被自动清理，共 **Remove 192 Packages**，`-y` 让它没有确认就执行了 → 删除操作不要加 `-y`，先看 Transaction Summary；补救用 `dnf history` + `dnf history undo <ID>`。
- 第 7 题：之后 `dnf install zip --disablerepo='*' --enablerepo=w2repo` 报 `nothing provides unzip needed by zip` → unzip 也被删了，而本地仓库里只有 tree 和 zip → 只启用一个仓库时，**依赖也必须在这个仓库里**。
- 第 7 题补救：`dnf history undo 25` **没加 -y**，看过 `Install 192 Packages` 再确认，全部恢复。
- `dnf config-manager set-disabled` 少了 `--` → 读 usage 提示后改成 `--set-disabled`。
- 第 12 题：服务 `status=203/EXEC` → systemd 无法执行 ExecStart 指定的程序。原因：脚本没有 `chmod +x`；另外脚本本身也不对：`watch` 是交互式命令，需要终端；`"$(date)"` 在脚本启动时只展开一次，时间永远不变；服务以 root 运行，脚本里不需要 sudo → 改为 `while true; do date >> /var/log/w2demo.log; sleep 10; done`。
- 第 13 题：drop-in 又写成 `override.service`（昨天热身同样的错）→ 必须 `.conf`。
- 第 8 题：`dnf providers` 拼错（是 `provides`）；`rpm -qc htpasswd` → `rpm -q` 系列跟**包名**，命令名要先 `rpm -qf $(which htpasswd)` 查包名。
- 第 9 题：普通用户执行 `rpm -V` 出现 `..?......` 和 `missing ... (Permission denied)` → `?` 表示没权限读取、无法检查，不代表文件有问题 → 校验要用 sudo。
- 第 10 题：`pgrep -a sleep 3000` 报 only one pattern → pgrep 只接受一个模式，按用户查用 `pgrep -au lisa`；改 lisa 的进程优先级、终止 lisa 的进程都需要 sudo（普通用户只能动自己的进程）。
- 第 10 题：`ps` 里每个 sleep 前面都有两个 `sudo -u lisa sleep 3000` 进程 → sudo 自己的进程（父进程 + 监视子进程），`jobs` 显示的 PID 是 sudo 的，真正的 sleep 是另一个 PID。
- 普通用户 fqh `ls /srv/webdata` 报 Permission denied → fqh 是"其他人"，权限 `---`，符合 3770 的设计，查看要用 sudo。

## 回忆题

1. （概念）`useradd -p RedHat2026 alex` 为什么不行？
<details><summary>答案</summary>

`-p` 需要已加密的哈希，明文被原样写进 shadow，登录时哈希比对永远失败。
</details>

2. （操作）alex 密码最长 60 天且下次登录必须改；之后新建用户默认最长 90 天。
<details><summary>答案</summary>

（设好密码之后）`chage -M 60 -d 0 alex`；编辑 `/etc/login.defs` 中 `PASS_MAX_DAYS 90`（只影响之后新建的用户）。
</details>

3. （排障）新建的用户怎么都登录不了，密码确认没输错，先查什么？
<details><summary>答案</summary>

`grep 用户 /etc/shadow` 看密码字段是不是正常哈希（是否被 `-p` 写成明文、是否 `!` 锁定）；Shell 是否为 nologin；`chage -l` 是否已过期。
</details>
