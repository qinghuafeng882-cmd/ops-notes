## 关键步骤

```bash
# 1 分区 + ext4
sudo wipefs -a /dev/sdd                          # -a 才擦除，-f 只是强制
sudo fdisk /dev/sdd                              # g、n +1G、n 回车、w
sudo mkfs.ext4 -L backup /dev/sdd1               # 对分区，不是整盘
sudo mkdir -p /backup
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdd1) /backup ext4 defaults 0 2" | sudo tee -a /etc/fstab
sudo findmnt --verify; sudo systemctl daemon-reload; sudo mount -a

# 2 swap
sudo mkswap /dev/sdd2
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdd2) none swap defaults 0 0" | sudo tee -a /etc/fstab
sudo swapon -a; swapon --show

# 3 LV + 在线扩容
sudo lvcreate -n web -L 300M datavg              # 旧签名提示全部 y
sudo mkfs.xfs /dev/datavg/web; sudo mkdir -p /web
echo "/dev/datavg/web /web xfs defaults 0 0" | sudo tee -a /etc/fstab
sudo dd if=/dev/urandom of=/web/test.bin bs=1M count=100
sudo md5sum /web/test.bin | sudo tee /root/web.md5
sudo lvextend -r -L 600M /dev/datavg/web         # 设定总量，不是 +600M

# 4 RAID1 换盘
sudo mdadm /dev/md0 --fail /dev/sdh
sudo mdadm /dev/md0 --remove /dev/sdh
sudo mdadm /dev/md0 --add /dev/sdh               # 输出 re-added

# 5 NFS + autofs
echo "/srv/nfs/web 192.168.56.0/24(ro)" | sudo tee /etc/exports.d/web.exports     # node1
sudo exportfs -rav; sudo exportfs -v
echo "/remote /etc/auto.web --timeout=30" | sudo tee /etc/auto.master.d/web.autofs # node2
echo "web -ro node1:/srv/nfs/web" | sudo tee /etc/auto.web
sudo systemctl restart autofs

# 6 tar
sudo tar cJf /backup/ssh-$(date +%F).tar.xz /etc/ssh
sudo tar tJf /backup/ssh-2026-10-20.tar.xz | head -5
sudo mkdir -p /tmp/restore
sudo tar xJf /backup/ssh-2026-10-20.tar.xz -C /tmp/restore etc/ssh/sshd_config
sudo diff /tmp/restore/etc/ssh/sshd_config /etc/ssh/sshd_config
```

## 踩坑

- `wipefs -f /dev/sdd` 没擦掉签名 → `-f` 是强制，`-a` 才是擦除全部。
- `mkfs.xfs -n backup /dev/sdd` → 三个错叠在一起：题目要 ext4；对象应是分区 sdd1 而不是整盘；卷标是 `-L`（`-n` 是命名参数）。XFS 提示 `appears to contain a partition table (gpt)` 拒绝执行 → **工具拒绝时先读懂原因，不要直接加 -f**，加了会覆盖刚建的 GPT。
- 不带 sudo 跑 `findmnt --verify` → 一堆 `Permission denied` 警告，结果不可信。
- `findmnt --verify` 里 `none … target specified more than once`、`/swapfile is a directory or regular file` → 多条 swap 挂载点都写 none、swap 文件本来是普通文件，属于正常警告，看 `0 errors` 即可。
- `mount -a` 不启用 swap → `swapon -a`。
- `lvcreate` 连续 11 次提示 `xfs_external_log signature detected` → LVM 不清零新分到的 PE，扫到旧 LV 的残留数据；新建的 LV 全部 y。
- df 显示 536M 而不是 600M → XFS 内部日志 16384 块 × 4KiB = 64MiB 不计入 df 的 Size。
- 加回同一块盘显示 `re-added` 且无重建 → write-intent bitmap：超级块还认得它，只同步离开期间改过的块（0 块）。`wipefs` 后再加或换新盘才会全量重建。
- `md5sum -c /root/raid.md5` 报 Permission denied → /root 下的文件要 sudo。
- `mount | grep remote` 只看到 autofs 那一行 → 超过 30 秒已自动卸载（推测）；马上 `ls` 再查就能看到 nfs4 行。
- 客户端映射写了 `-ro`，所以 `touch` 失败证明不了服务端 ro → 改成 `-rw` 做对照。
- `sed -i 's/-.*ro.*/-rw/'` 把整行后半段替换掉 → `.*` 贪婪匹配；有备份，直接还原。
- 普通用户 `sed -i` 改 /etc 下文件报 `couldn't open temporary file /etc/sedXXXX` → sed -i 先在同目录建临时文件再替换，需要目录写权限（也说明会产生新 inode）。
- `tar -C /tmp/restore` 报 `Cannot open` → 目录要先 `mkdir -p`。
- 第 7 题：`lsof -L1` 写错，应为 `lsof +L1`。

## 卡点 / 没想明白的

- 第 7(b) 只想到一种原因。第二种：/web 下面某个子目录上又挂了别的东西，盖住了 /web 自己文件系统里的数据——df /web 算它，du 看不到 → `sudo mount --bind /web /mnt/webview; sudo du -sh /mnt/webview`（bind 不带子挂载）。批改时我一开始说成"占根分区"，那是 /data 没挂上那种场景，不适用于 /web 本身 100%，已更正。

## 回忆题

1. （概念）mdadm 加回原来那块盘为什么显示 `re-added`、瞬间就 `[UU]`？
<details><summary>答案</summary>

阵列有 write-intent bitmap，盘上的超级块还带着阵列 UUID，md 只同步它离开期间被写过的块，这期间没写入所以没东西要同步。擦掉签名或换新盘会走 `added` + 全量 recovery。
</details>

2. （操作）在线把 /dev/vg/web 扩到总共 600M，并确认数据完好。
<details><summary>答案</summary>

`sudo lvextend -r -L 600M /dev/vg/web`（不带 +）→ `df -hT /web` → `sudo md5sum -c /root/web.md5`
</details>

3. （排障）`df` 显示 /web 100%，`du -sh /web` 只有 30M，两种可能和验证方法？
<details><summary>答案</summary>

① 文件已删除但仍被进程打开：`sudo lsof +L1`，重启该进程或 `: > /proc/PID/fd/N`。② /web 内某个子目录上有子挂载，盖住了 /web 文件系统自己的数据：`findmnt -R /web` 看子挂载，`mount --bind /web /mnt/webview` 后 `du -sh /mnt/webview`。
</details>
