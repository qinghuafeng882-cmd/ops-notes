# 网络基础：NetworkManager / nmcli、名字解析

- 日期：2026-10-21（W4-D1）
- 考点：RHCSA EX200 —— 配置 IPv4 和 IPv6 地址；配置主机名解析；网络服务开机生效
- 环境：Rocky Linux 10.2（VirtualBox），node1 + node2；enp0s3 = NAT，enp0s8 = host-only
- 状态：完成
- 来源：根据课程对话和终端记录整理

## 目标

搞清楚 device 和 connection 的关系、"改配置"和"生效"是两步，在 host-only 网卡上配持久化的 IPv4 第二地址和 IPv6 静态地址，理解名字解析的顺序。

## 关键概念

- **device** = 实际网卡（`enp0s8`），内核识别后出现；**connection** = 配置（profile），存在 `/etc/NetworkManager/system-connections/*.nmconnection`。一块网卡可以有多个 profile，同时只激活一个。本机两个 profile 恰好和网卡同名。
- `nmcli con mod` 只改 profile 文件，`nmcli con up` 才应用到网卡；`ip addr add` 只改运行状态，不保存。
- `con up` 会按 profile **重置**网卡地址：`ip addr add` 加的地址会被清掉（实验 3 实测）。
- 手动改 keyfile 后要 `nmcli con reload` 再 `con up`。
- keyfile 权限 600：文件里可能有明文密钥/密码，**group 或 other 可读写的 keyfile 会被 NM 忽略**（nm-settings-keyfile 文档）。
- RHEL 10 **移除**了 ifcfg 格式支持（不是"不推荐"），`/etc/sysconfig/network-scripts/ifcfg-*` 根本不会被读取；teaming 也删了，用 bond。
- `ipv4.method`：`auto` = DHCP，`manual` = 静态（必须带 addresses），`disabled` = 不配。`fe80::` 链路本地地址总会自动生成。
- 名字解析按 `/etc/nsswitch.conf` 的 `hosts: files dns myhostname`：先 `/etc/hosts`，再 DNS，最后 myhostname（本机主机名）。`getent hosts` 走同一条路径；`dig`/`nslookup` 只查 DNS。
- `/etc/resolv.conf` 由 NM 生成（第一行 `# Generated by NetworkManager`），手动改会被覆盖；enp0s8 的 `ignore-auto-dns=true` 表示不用 DHCP 给的 DNS。
- 默认路由 `default via 10.0.2.2 dev enp0s3`：上外网走 NAT 网卡。

## 关键步骤

```bash
# 现状
nmcli device; nmcli connection show
ip -br addr; ip route; cat /etc/resolv.conf
sudo cat /etc/NetworkManager/system-connections/enp0s8.nmconnection

# 持久化第二个 IPv4（+ 追加，不加 + 会覆盖 .11 导致 SSH 断开）
sudo nmcli con mod enp0s8 +ipv4.addresses 192.168.56.111/24
sudo nmcli con up enp0s8

# 运行时地址 vs 持久化
sudo ip addr add 192.168.56.112/24 dev enp0s8
sudo nmcli con up enp0s8          # .112 消失
sudo reboot                       # .111 还在

# IPv6 静态（node2 同理 ::12）
sudo nmcli con mod enp0s8 ipv6.method manual ipv6.addresses fd00:56::11/64
sudo nmcli con up enp0s8

# 名字解析
grep ^hosts /etc/nsswitch.conf
echo "192.168.56.111 web1" | sudo tee -a /etc/hosts
getent hosts web1; ping -c1 web1; dig web1

# 删除第二地址
sudo nmcli con mod enp0s8 -ipv4.addresses 192.168.56.111/24
sudo nmcli con up enp0s8
```

## 踩坑

- 热身（W3 复习）3/3；第 1 题把 `UUID=$(blkid ...)` 直接当成 fstab 内容 → fstab 不是 shell，不会展开 `$(...)`；要么 `echo "..." | sudo tee -a /etc/fstab` 让 shell 先展开，要么写展开后的 UUID。
- `cat .../enp0s8.connection` → No such file → 后缀是 `.nmconnection`。
- node2：`nmcli con mod ipv6.method manual ...` → `unknown connection 'ipv6.method'` → 漏了连接名，nmcli 把第一个参数当成连接名。
- `nmlic` 拼错。
- keyfile 权限 600 的原因一开始答成"不允许手动修改" → 实际可以手动改（改完 `con reload`），600 是因为文件里可能有明文密钥，权限不对 NM 直接忽略这个文件。
- 达标题 4 答成"被弃用" → RHEL 10 是**移除**，ifcfg 文件完全不读。

## 回忆题

1. （概念）`nmcli con mod` 和 `ip addr add` 分别改了什么？哪个重启后还在？
<details><summary>答案</summary>

`con mod` 改 profile 文件，要 `con up` 才生效，重启后还在；`ip addr add` 改内核运行状态，立即生效，`con up` 或重启后消失。
</details>

2. （操作）给连接 enp0s8 追加 192.168.56.111/24，再配 IPv6 静态地址 fd00:56::11/64，立即生效。
<details><summary>答案</summary>

`sudo nmcli con mod enp0s8 +ipv4.addresses 192.168.56.111/24 ipv6.method manual ipv6.addresses fd00:56::11/64 && sudo nmcli con up enp0s8`
</details>

3. （排障）`ping web1` 通，`nslookup web1` 查不到；另一台机器手动改了 `/etc/resolv.conf`，过几天 DNS 又没了。各自原因？
<details><summary>答案</summary>

ping 走 nsswitch（先 /etc/hosts），nslookup 只查 DNS，不矛盾。resolv.conf 由 NM 生成，会被覆盖 → `nmcli con mod 连接 ipv4.dns "x y"`（DHCP 连接再加 `ipv4.ignore-auto-dns yes`）+ `con up`。
</details>
