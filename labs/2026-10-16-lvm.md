# LVM 逻辑卷管理

- 日期：2026-10-16（W3-D2）
- 考点：RHCSA EX200 —— 创建和删除逻辑卷；不破坏数据地添加分区和逻辑卷；扩展现有逻辑卷
- 环境：Rocky Linux 10（VirtualBox），sde、sdf
- 状态：完成
- 来源：根据课程对话和终端记录整理

## 目标

拆掉旧 lab-vg，从零建 datavg，练在线扩容、缩小、加盘、pvmove 换盘、写 fstab，最后在线扩容根分区。

## 关键概念

- PV（打了标签的磁盘/分区）→ VG（存储池）→ LV（从池里划出的块设备）→ 文件系统。
- PE 默认 4MiB，LV 由一串 PE 组成，**可以不连续、可以跨盘** → 跨盘、在线扩容、在线迁移都靠它。LV 大小是 PE 的整数倍。
- LVM 管元数据（写在每个 PV 开头，另有 `/etc/lvm/backup`、`archive`），内核 device-mapper 干活：`/dev/datavg/app` = `/dev/mapper/datavg-app` → `/dev/dm-N`。LV 路径稳定，可写进 fstab。
- 缺一块 PV → VG 部分可用，LV 默认不激活；`vgreduce --removemissing` 会损坏跨该盘的 LV。**LVM 没有冗余**。
- `lvs` Attr 第 5 位 `a` = 激活，第 6 位 `o` = 已打开（挂载）。
- 扩容：先 LV 后文件系统；缩小：先文件系统后 LV。**一律加 `-r`**。`-L +500M` 是增加，`-L 500M` 是设定总量。
- XFS 不能缩；ext4 缩小要先卸载。
- 删除从上往下：umount + **删 fstab 行** → lvremove → vgremove → pvremove。

## 关键步骤

```bash
# 拆旧 VG
sudo umount /mnt/lvm-lab; sudo lvremove /dev/lab-vg/data-lv; sudo vgremove lab-vg; sudo pvremove /dev/sde /dev/sdf

# 新建
sudo pvcreate /dev/sde; sudo vgcreate datavg /dev/sde
sudo lvcreate -n app -L 1G datavg; sudo lvcreate -n logs -L 300M datavg
sudo mkfs.xfs /dev/datavg/app; sudo mkfs.ext4 /dev/datavg/logs

# 数据指纹
sudo md5sum /mnt/app/test.bin | sudo tee /root/app.md5; sudo md5sum -c /root/app.md5

# 扩容（不加 -r 需手动第二步）
sudo lvextend -L +200M /dev/datavg/app && sudo xfs_growfs /mnt/app
sudo lvextend -r -L +100M /dev/datavg/logs

# VG 满了 → 加盘
sudo pvcreate /dev/sdf; sudo vgextend datavg /dev/sdf; sudo lvextend -r -L +500M /dev/datavg/app
sudo lvs -o +devices datavg

# ext4 缩小
sudo umount /mnt/logs; sudo lvreduce -r -L 300M /dev/datavg/logs; sudo mount /dev/datavg/logs /mnt/logs

# 在线换盘
sudo pvmove /dev/sde; sudo vgreduce datavg /dev/sde; sudo pvremove /dev/sde

# 在线扩容根分区
sudo lvextend -r -L +500M /dev/rlm/root
```

## 验证

| 检查项 | 命令 | 预期结果 | 结果 |
|---|---|---|---|
| rlm 空闲空间 | `vgdisplay rlm` | Free PE × 4MiB = VFree | ✅ 255 × 4MiB = 1020MiB |
| 旧 lab-vg 拆除 | `pvs`、`lsblk -f` | sde、sdf 无签名 | ✅ |
| 不加 -r | `lvextend` 后 `df` | LV 变大、df 不变 | ✅ 960M 不变，`xfs_growfs` 后 1.2G |
| VG 空间不足 | `lvextend -L +2G` | 拒绝 | ✅ `512 extents needed, but only 105 available` |
| app 跨两块盘 | `lvs -o +devices` | sde + sdf | ✅ |
| XFS 缩小 | `lvreduce -r -L 1G` | 拒绝 | ✅ `reduce is required and not supported (xfs)` |
| ext4 缩小 | `cat hello.txt` | 数据还在 | ✅ |
| pvmove | `pvs -o +pv_used`、`md5sum -c` | sde 用量 0，数据 OK | ✅ |
| 重启后挂载 | `df -hT`、`md5sum -c` | 都挂载，OK | ✅ |
| 根分区扩容 | `df -h /` | 25G → 26G | ✅ 25.48g |

## 踩坑

- fstab 写成 `/etc/datavg/app`（应为 `/dev/...`）→ `findmnt --verify` 报 `unreachable source` → 用 vim 改正后再重启。
- 修正时 sed 两次失败：分隔符混用 `|` 和 `/`（unterminated `s` command）、文件名打成 `/etc/fslab`。
- `lvcreate` 提示 `xfs signature detected ... Wipe it?` → 旧 data-lv 的签名残留，新 LV 输入 y。
- `pvdisplay /dev/rlm/sdb`、`df -h /dev/app` 路径写错；`ls /etc/lvm/backup` 需要 sudo。
- 热身：取 UUID 忘了 `blkid -s UUID -o value`；fstab 检查写成 `fscheck -N1`（应为 `findmnt --verify`）；busy 排查命令忘了（`fuser -vm`/`lsof`，子挂载 `findmnt -R`）。
- 达标题第 7 题不会：删除 LV 前最容易漏的是**删 fstab 里的那一行**，漏了下次开机进紧急模式。

## 回忆题

1. （概念）为什么 `lvextend` 之后 `df` 看不到变化？
<details><summary>答案</summary>

只扩了 LV（块设备），文件系统超级块记录的大小没变；要 `-r`，或补 `xfs_growfs 挂载点` / `resize2fs 设备`。
</details>

2. （操作）`/data` 在 LV `/dev/vg0/data` 上，VG 没空间，新接了 `/dev/sdx`，写出扩容命令。
<details><summary>答案</summary>

`pvcreate /dev/sdx; vgextend vg0 /dev/sdx; lvextend -r -l +100%FREE /dev/vg0/data; df -hT /data`
</details>

3. （排障）同事删掉了一个 LV，重启后服务器进了紧急模式，最可能的原因？
<details><summary>答案</summary>

fstab 里还留着那个 LV 的挂载条目，开机找不到设备。
</details>
